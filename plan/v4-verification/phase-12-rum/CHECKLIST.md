## What was built

| Task | What |
|---|---|
| G12.1 `RewardConfig` | `rewards.saltwind` (`V4/Data/Rewards/SaltwindRewards.asset`, generated by `V4RewardConfigGenerator` from the V3 profile's Marks economy): rows {id, label, source, Rum per credit, kills per minute, max credits, max Rum}. Sources: QualifyingMinute, OvertimeMinute, SpecialLandmark, ScheduledElite, BossVictory, ChestOpened. Defaults = V3 (2/≥10, 3, 5 max 2, 25 once, 3/≥10 capped 15); an extra "1 Rum per chest" row, off by default. Currency name "Rum" |
| I12.1 `RewardModule` | Event-driven (`Runtime/Rewards`): Killed (now published by the V4 kill fan-out with the unit id and the run-clock time), LandmarkUsed, BossState 2, PhaseChanged (a focus spawn's unit id registers a scheduled elite), ChestOpened. Minutes are closed by the run clock at settlement exactly as V3's tracker closed them (the minute in progress never counts; overtime minutes pay once the next begins). `Settle(runId)` once: includes events published in the dying frame but not delivered yet; later calls return the first result and pay nothing; pays through `IRumBank` (`SaveRumBank` → `SaveService.TrySettleRun`, one receipt per run id; the saved field stays `marks`) |
| Death flow | `LegacyRunLifecycle.OnPlayerDied` (was `LegacyRewardsAdapter`): secure a same-tick boss, conquest unlock, PlayerDead → **settle Rum** → RunComplete, onboarding, telemetry; never `FinalizeRunOnDeath` (no Doubloons, run gold not banked); toasts "Run ended." and "Rum settled: +N" (R-59). | `UnlockService` | Port of SaltwindMarksUnlockLogic on V4 config: goal = next unowned weapon in `UnlockConfig.weaponUnlocks`; costs from `UnlockConfig` / `CaptainConfig.rumCost`; purchase via the shared save; texts in Rum |
| N12.1 Results | `RunResultsView` (V4 `IResultsView`): Rum breakdown per enabled row + treasury, goal, damage share from the weapon module's per-hit records (`DamageShareTracker`, same ids and names as V3's results); run facts from the kept run manager passed in by the view factory. | Adapters | Reward work removed from `LegacyStageRewards` (special POI, boss), `LegacySpawnFeedback` (scheduled elites), the kill fan-out (Marks credit), `LegacyHudCommands` (unlocks), `LegacyResultsTelemetry` (reads the Rum total); what remains (telemetry, toasts, home seed, chest trigger, boost/restart/menu, ship combat and the telemetry ledger) is retagged M14. `V4Phase.Current = 12` |

## Independent review

A read-only reviewer checked M12 against V3's Marks code and the old death flow. Confirmed: minute attribution equals V3 under any script order (V3 advances the clock and closes minutes in the same RunManager.Update); boundary rules, caps and the 57 fixture; no double counting (Pending read once, later deliveries ignored, one Killed per kill; the difficulty director still counts each kill once); death-flow order; no adapter tagged ≤ 12; unlock costs and ownership aliases; no "Marks" in presentation. Findings and fixes:

| # | Finding | Fix |
|---|---|---|
| 1 | Major: the results damage share dropped cutlasses, flamethrower, trail, lightning and mortar (their enemy hits carry no weapon tag) | The share listens to the weapon module's per-hit records (the ids V3's results used), with V3's display names; test added |
| 2 | "Ended by death" was never set in the V4 flow (run-status view) and not in the Module Lab | The run-status view reads the Rum settlement; the lab sets it too |
| 3 | A victory that ends the run (continue-after-boss off, non-default) paid Doubloons through V3's CompleteRun and settled no Rum | V4 ends that run itself: objective, Rum settled once, no Doubloons; PlayMode test |
| 4 | Without a save V3's marks line is zeros while V4 still computes | Trace players always have a save (the trace set confirms) |
| 5 | The console jump attributes a kill in the jump frame to the new minute (V3: old) | Dev-console only; noted |
| 6 | The "second finalize" assertion could not fail | The test now calls the death flow a second time |
