Every line before the first difference matches exactly (spawns, kills, levels, the first level-up cards, the Loot stream).
Cause: the run's offer context dropped V3's unlock rule. V3's LevelOfferGenerator.IsWeaponOfferEligible offers a new weapon
only if it is enabled AND, while V3RunContext is active (every run), unlocked (a starter or owned). V4's run wiring passed
only the enabled check, so a fresh save was offered locked weapons (Powder Kegs, Flamethrower). The Editor lockstep tests ran
with V3RunContext off, where V3 does not filter either, so they could not see it.
Fix: LegacyBuildWiring.IsWeaponOfferEligible is V3's rule (enabled, and unlocked while V3RunContext is active); the offers
lockstep test now runs half its 600 builds with V3RunContext on and locked weapons, and asserts the other half would have
offered a locked weapon (6/6 green).
Per the standing rule the trace set is not re-run after the fix; the lockstep test verifies it.
