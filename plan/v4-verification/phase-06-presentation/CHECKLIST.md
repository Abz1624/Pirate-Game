## What M6 delivers

**Views.** Presentation now reads only read-only views (`Runtime/Views/RunViews.cs`: run status, ship, captain, progression, loadout, stage, enemies, results) plus the event stream, and forwards button presses through a small command interface (boost, retry, menu, unlock goal). M6 implements the views over the legacy hubs (`Runtime/Legacy/LegacyViews.cs`, each tagged with the phase that replaces its hub); later phases swap in V4 modules without touching the presenters. Hub lookups are cached and retried at most every 30 frames when missing (V3 searched the scene every frame, R-63).

**Presenters** (`Presentation/Hud`), each a port of its V3 view with the same layout, texts, colours and timings:

| V4 presenter | Replaces | Notes |
|---|---|---|
| `AuthoredHudPresenter` | V3AuthoredGameplayHud | Binds the authored `/Canvas` widgets: timer (red in overtime), gold, kills, captain portrait/name/level, hull and XP bars, quest list, boost meter. Lays out against the minimap |
| `LoadoutHudPresenter` | V3AuthoredBottomLoadoutHud | Weapons bottom-left, Logbooks over Items bottom-right; names from the V4 weapon/evolution configs (the evolved name after evolving); rewrites a slot only when it changes |
| `IconCatalog` (asset) | V3RunHudIconResolver | Direct sprite references, so icons also show in player builds (V3 loaded them with the Editor-only AssetDatabase). R-90 |
| `MinimapPresenter` | V3MinimapHud | Same settings and art assets; fog, bounds veil, POI glyphs, beacon sector, boss/miniboss glyphs, spawn pings. Glyphs built once (R-86 fixed) |
| `BeaconGuidePresenter` | V3BossBeaconGuide | Violet skylight and screen arrow from beacon discovery until the boss is summoned |
| `ResultsPresenter` | both V3RunResultsScreen copies | Same panel, summary and buttons; opens on the RunComplete event; Retry reloads the V4 run, Main menu loads the V4 menu. One copy (V3 stacked two, R-63) |
| `SpawnWarningPresenter` | V3SpawnTelegraph, V3SpawnWarningHud, V3SpawnEdgeIndicator | Driven by Spawned events flagged ambient: Captain/General-tier toast (1.5 s throttle), 3 s minimap ping, 2.5 s edge chevron |

**Weapon effects** (carried over from M5): `WeaponVfxPresenter` draws everything V3's `WeaponJuiceController` drew (muzzle, Long Nine beam, broadside salvo, powder kegs and their blast, lightning, mortar reticle and impacts, burning oil, boarding skiffs, orbit blades at the simulation's hit spheres) through the view pool; `WeaponAimOverlay` replaces `WeaponTargetingVisualizer` (O/V/backslash, every shape). The weapon module reaches the presenter through `WeaponEffectsForwarder` (no presenter → effects skipped, handles -1). V3 chose muzzles, overlay shapes and impact scales by weapon id; those choices are weapon config now (`WeaponConfig.visual`, `WeaponRulesConfig` blast/impact bindings, generated by `V3ConfigMigrator.ApplyM6Visuals` with V3's values). The flame stream stays `FlameStreamPresenter` (M5, R-89).

**Events.** Ambient spawns carry `CombatEventFlags.AmbientSpawn` (the spawn warnings read them). New legacy feeds: OffersShown (level-up cards), BeaconState, BossState and LandmarkUsed (polled once a frame; V3 had no events for them). OfferChosen and PlayerHealed have no legacy signal; their native producers come with M9 and M8.

**Tuning Console → Events**: counts per kind (from run start), a filterable log of the last 400 events, and **Export session** (event log, tuning change log, current preset and config hash in one JSON file under `persistentDataPath/V4/Sessions`).

**Run UI setup.** `V3RunUiBootstrap.EnsureAll` is no longer called (it would re-add the V3 HUD, results screen, minimap, guide and even a LevelSystem). `LegacyPresentationAdapter.EnsureRunUi` reproduces what it did for the pieces that stay, in its order: event system, run canvas, legacy RunHud and level-up modal layout, discovery, toasts, interaction prompts, hiding placeholder duplicates.

**Scenes** (`V4SceneSetup.ApplyM6`): V3AuthoredGameplayHud (the one the `/Canvas` prefab carries, removed as a scene override, and the one added in the scene) and both V3RunResultsScreen leave V4SaltwindRun and V4ModuleLab. The shared prefab is unchanged.

## Independent review

No blockers. Fixed:
- **Major:** presenters still reached legacy or internal code (the legacy hazard ring view and VFX broker from the weapon presenter, the weapon manager's targeting/enemy query/modifiers from the aim overlay and blade drawing, the playtest flag from the presentation root), and the isolation test missed it (fixed name list). Now: a read-only `IWeaponAimView` (target, cluster point, arc, Size stat, directional flag), `IWeaponManager.OrbitHits`, the playtest flag on the run status view, the timed ring and water splash sent to the legacy views by the runtime forwarder; the test bans the `RoguePirates.V4.Legacy` namespace, the VFX broker, the playtest flag and the weapon module's concrete types.
- LandmarkUsed had no producer: now polled (landmark slots turning used; chests and the Beacon have their own events).
- `EnsureRunUi` hid V3's placeholder HUDs even without an authored HUD canvas: now only when one exists, else V3's fallback HUDs, as `EnsureAll` did.
- Two legacy types had no deletion phase: tagged, and a test now requires it for every legacy type.
- Tests added: feeds once each, hull/XP bars, results telemetry once, profile back after Retry.
- The Events log has its own filter box (the console search box emptied it); the results panel sits below the toast and prompt views as in V3 (unlock-goal toasts draw over it).
- The Editor's runtime font-atlas change was reverted before commit.

Checked by the review and found correct: scene removals (including the prefab's own HUD), `EnsureRunUi` order, results flow and texts, every presenter against its V3 source, blade timing, the forwarder and pooling, no change to simulation or random draws, content-id rule. The disabled juice controller still plays V3's hellfire burning oil and enemy blasts (code confirmed: instantiate + timed destroy and the broker pool, no Update dependency).
