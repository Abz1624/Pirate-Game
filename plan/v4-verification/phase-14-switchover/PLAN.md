## Intended simulation changes (explained in the final trace comparison)
1. **Pickups on their own seeded stream** (M14.8): `PickupModule` used `UnityEngine.Random`, which presentation code
   (damage numbers, camera shake, VFX, chest bob) also draws from — moving or removing any VFX moved pickups.
2. **Pooled enemy views without R-81/R-72** (M14.10): new enemy models no longer keep island colliders for a frame and
   no longer toggle `/Systems`.
3. **Chest interaction range to the logical POI position** (M14.12, R-95), not the bobbing marker.
4. **One frame driver after the run clock** (M14.14, found by the independent review): the V4 run ticks used to run from
   update slots at execution order 0, interleaved (by scene file ID and creation order) with the kept order-0 shared
   components — the run manager, the ship, its damage receiver and boost. Now one driver at order 10 runs them all, in the
   captured order, after every order-0 component: each tick sees this frame's clock and the ship's post-move position.

**Deviation — build list** (M14.15): the decision was "V4 scenes only in builds". Builds do contain only the V4 scenes
(V4Boot first; the trace launcher only in development builds): `V4BuildSettings` filters every Build-window build and
`BuildRelease` passes them explicitly. The Editor build list keeps the V3 and test scenes enabled after the V4 ones
because V3's regression PlayMode tests load them by name, which the Editor only allows for enabled list scenes; M15
removes them. A script calling `BuildPipeline.BuildPlayer` with `EditorBuildSettings.scenes` would include them.
